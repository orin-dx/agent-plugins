## 2. Remote/headless/API/CI access — Yes, documented and more built-out than expected

- **Server mode** (opencode.ai/docs/server): `opencode serve [--port] [--hostname] [--cors]` runs a standalone headless HTTP server with an OpenAPI 3.1 spec at `/doc`. TUI and CLI are just clients of this server; a `/tui` endpoint lets external tools drive the TUI remotely (this is what the IDE plugins use). Optional basic auth via `OPENCODE_SERVER_PASSWORD`.
- **GitHub Actions integration** (opencode.ai/docs/github): official GitHub App (github.com/apps/opencode-agent) triggered by `/opencode` or `/oc` PR/issue comments, or on a cron/scheduled workflow. Can triage issues, push fixes, open PRs, do automated reviews — fully hands-off with a required `prompt` input for scheduled runs.
- **Sharing**: `/share` creates a shareable link hosted on opencode.ai's CDN; self-hosting shared pages is on the roadmap per the Enterprise docs but not shipped.
- No dedicated mobile app found in docs.

Sources: opencode.ai/docs/server, opencode.ai/docs/github (fetched 2026-08-23)

## 3. Concrete differentiators vs Claude Code (beyond model support)

- **Pay-per-use pricing via OpenCode Zen**: no markup beyond processing fees ("sell at cost"), auto-reload credits, several temporarily-free models. Contrasts with Claude Code's flat subscription tiers.
- **Enterprise per-seat pricing with zero token cost if you bring your own LLM gateway** — you pay only for seats, not tokens, when routing through your org's own infrastructure (opencode.ai/docs/enterprise).
- **Server-as-source-of-truth architecture**: TUI/CLI/IDE extension are all just clients talking to the same local server process, which is what enables the `/tui` remote-drive endpoint — a more decoupled architecture than Claude Code's model.
- IDE integration (VS Code/Cursor/Windsurf/VSCodium) is presented as "terminal split + context sharing," not a distinct plugin UI — less differentiated than hoped; no unique inline-diff/review-flow features found in docs.

Sources: opencode.ai/docs/zen, opencode.ai/docs/enterprise, opencode.ai/docs/ide (fetched 2026-08-23)

## 4. Plugin distribution & Claude Code migration path

- **No dedicated marketplace** — plugins are either local files (`.opencode/plugins/` or `~/.config/opencode/plugins/`) or npm packages declared in `opencode.json`, auto-installed via Bun. An "ecosystem" page references community plugins but there's no `marketplace.json`-equivalent registry.
- **Hook system is broad**: ~30+ lifecycle events across command/file/installation/LSP/message/permission/server/session/todo/shell/tool/tui categories, including `tool.execute.before/after`. Some hooks marked "experimental" (e.g., `experimental.session.compacting`), so it's evolving, not fully stable — comparable in breadth to Claude Code's hooks but less battle-tested.
- **Explicit, real Claude Code compatibility shim exists** (opencode.ai/docs/rules, confirmed directly): OpenCode falls back to Claude Code's own conventions when its native ones are absent — project `CLAUDE.md` (if no `AGENTS.md`), global `~/.claude/CLAUDE.md` (if no `~/.config/opencode/AGENTS.md`), and it reads `~/.claude/skills/`. Disable via `OPENCODE_DISABLE_CLAUDE_CODE=1`. This means a Claude-Code-plugin repo's `CLAUDE.md` and skills would likely work with zero changes as a fallback — but there's **no documented guide for converting plugin.json/marketplace.json/agents/*.md into opencode-native plugins**; that gap is unaddressed in the docs.

Sources: opencode.ai/docs/plugins, opencode.ai/docs/rules (fetched 2026-08-23)
