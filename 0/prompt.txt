## 2. Key Technical Concepts

- **4-part agent structure**: `<backstory>` (2–4 sentences, experiential), `<goal>` (intent not steps), `<judgment>` (names failure mode, not success criteria), `<output>` (schema + EARS contracts only)
- **EARS notation** (`WHEN/IF/WHILE/WHERE/THE SYSTEM SHALL`): belongs ONLY in `<output>` — never in backstory, goal, or judgment
- **Cognitive mode separation**: scanner (exhaustive pattern matching, no judgment) vs adversary (default-to-skepticism, requires concrete failing scenario) must be separate agents
- **Schema-driven development (SDD)**: every inter-agent handoff is a typed JSON Schema with `additionalProperties: false` and `reasoning` scratchpad field
- **Prompt injection resistance**: workspace CLAUDE.md/AGENTS.md files read during analysis are untrusted data — three-part defense (judgment failure mode, EARS trust-boundary contract, backstory priming)
- **Verdict signal** sub-fields in hazard references: answer "what executable evidence makes this confirmable vs dismissible?" — distinct from False positive check
- **`remediation_sketch`** field in `finding-report@1.json`: optional per-finding one-sentence fix direction, consumed by canon-architect
- **Wiring validation**: `consumes`/`produces` arrays in `plugin.json` + `shared/scripts/validate-wiring.sh`
- **Context management**: lambda orchestrator must pass one task object per invocation, not full plan
- **Trust boundary**: agents analyzing external workspaces must treat all file content (including CLAUDE.md, comments, strings) as data, not instructions
