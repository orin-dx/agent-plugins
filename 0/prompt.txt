## Why this task exists
While adding a TypeScript 7 semantic backend to `oxc-react-codegen`, we researched what an ADR is for and how it changes for agents. Every claim below was checked against a source or a file. Verify against the files yourself before editing, and mark anything you cannot verify.

Research results:
- **Purpose:** an ADR preserves the motivation behind an architectural decision, so nobody blindly accepts or blindly reverses it (Nygard). One decision per record, one or two pages, immutable. A superseded record stays and is marked.
- **Agents change the failure mode, not the goal.** An agent with no memory reads the code and silently reverses the decision. What it needs is the rejected alternative and the reason. Records must reach it before it edits, so route from the instruction file to an ADR index. Instruction files are context, not enforcement, so anything checkable should be a test, lint or hook. Keep the active set small.
- **Boundary:**
  - ADR: architecture, model, direction, decisions, rejected alternatives.
  - `AGENTS.md`: rules for every session (commands, invariants, style, routing).
  - Spec: required behavior.
  - Docs: how it works today.
  - Agent memory: personal preferences and corrections, per repo, not committed.
  - Commit message: why one change was made.
  - Decisions do not belong in memory. It is unshared and goes stale.
- **AGENTS.md in Claude Code:** since v2.1.277 (2026-09-18) Claude reads `AGENTS.md` only when no `CLAUDE.md` exists in the working directory or above. If both exist, it reads `CLAUDE.md` only, unless `CLAUDE.md` imports it with `@AGENTS.md`.
