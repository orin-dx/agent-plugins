# michi (道)

AXI response primitives for agent-ergonomic tools — TOON lists, key-value blocks, truncation, structured errors, status, and `help[]` hints.

`michi` is the formatting and response layer for the **orin-axi** suite: it turns structured data into token-efficient, agent-readable text. No CLI framework or async runtime required.

Available as a Rust crate (`michi`) or a Node.js package (`@orin-axi/michi`).

> [!IMPORTANT]\
> Not yet published to crates.io or npm. Clone the repo and build from source to try it — see [Local Development](#local-development).

## Why TOON?

Agents pay for every token they read. Standard JSON lists repeat keys on every single object, burning context window capacity:

```json
[
  { "number": 51815, "title": "[Bug]: Telegram plugin", "state": "open" },
  { "number": 51812, "title": "dark mode request", "state": "open" }
]
```

TOON (Token-Optimized Object Notation) states field names once in a tabular header:

```text
issues[2]{number,title,state}:
  51815,[Bug]: Telegram plugin,open
  51812,dark mode request,open
```

Values are quoted only when they contain commas, quotes, or newlines — no quoting overhead on the common case.

## Escaping

- Values containing commas **must** be quoted
- Values containing double quotes use a backslash escape: `\"`
- Embedded newlines and carriage returns are silently stripped, not escaped — TOON has no multi-line cell format
- Null/absent values render as an empty scalar: `val1,,val3`
- Booleans: `true` / `false`
- Numbers: unquoted

Useful later additions:

- `notify` for daemon-mode invalidation after filesystem changes.
- `zstd` if cached briefing/source snapshots become materially large.
- `petgraph` only if artifact-graph algorithms become more complex than SQL recursive queries and small in-memory traversals.
- `insta` and `proptest` for deterministic output and schema/graph property tests.

- `tantivy`: Monokl intentionally avoids a persistent code-search index.
- vector/embedding crates: optional Wisp semantic retrieval feature only.
- `sqlx`: not needed unless Wisp genuinely becomes a networked async service.
- a generic workflow engine: Wisp should provide evidence and state, not become another agent runtime.

The useful heuristic is: **Rayon analyzes, Tokio serves, SQLite relates, Michi renders, Monokl understands code, Wisp decides relevance.**
