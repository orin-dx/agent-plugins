2. The semantic-sibling search is the part most likely to be theater. Luu's formal-methods finding was that agents technically invoke a tool but prove trivial/irrelevant properties. "Search for semantic siblings — same domain responsibility expressed differently" is a much harder, fuzzier ask than syntactic grep, and the schema's only real guardrail is requiring evidence and a match count (including zero). That forces the agent to claim it searched, but doesn't verify the search was any good — an agent could report "matches": 0 with a thin evidence string and pass schema validation while having done a shallow pass. Given Luu's finding that agents' shallow-but-plausible-looking outputs are the dominant failure mode, I'd want a spot-check mechanism here — e.g., have exit-gate independently re-run the semantic search on a sample of families rather than trusting reviewer's self-report, the same way exit-gate already refuses to trust remediator's description of a fix.

3. Nothing addresses proptest/fuzzing-style structured input exploration, which Luu found was one of the few things that reliably added value (via shrinking). This ecosystem's testing story is entirely mutation-testing + example-based tests; there's no equivalent of "generate structured random inputs and shrink the failing case" anywhere in smith. If bug-prone logic in a target codebase is best caught by property-based exploration rather than hand-written examples, this pipeline has no lever for it at all — mutation testing only tells you your existing tests are weak, not that you're missing a whole input-space region no example covers.

4. Watch the token/instruction-economy tradeoff you're actively making. The new Instruction Economy section is a good instinct (Luu found bloated official skills reread ~20k tokens/run for no benefit), but it's now in tension with the constitution's own byte-identical <constitution> block being repeated in all ~40 agents — that block itself hasn't been trimmed by the new economy rule, and every new EARS rule added there (there are now ~15 sections) grows what's cached and reread by every single agent regardless of relevance to its phase. Worth an audit pass: does every agent actually need every constitution clause, or has it become the same kind of "comprehensive reference nobody trims" problem the economy rule was written to prevent elsewhere?
